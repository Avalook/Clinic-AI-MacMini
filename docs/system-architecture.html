Luồng xử lý Request

Từ browser đến DB — mọi request đi qua 3 lớp middleware (Request-ID → API-Key → DB Error Guard) trước khi đến router.

    participant C as 🔒 Caddy
    participant D as 📱 Dashboard
(Next.js)
    participant M1 as 🏷️ RequestID
Middleware
    participant M2 as 🔑 API-Key
Middleware
    participant M3 as 🛡️ DB-Error
Middleware
    participant R as 🛣️ Router
    participant S as ⚙️ Service
    participant DB as 🗄️ Supabase DB

    B->>C: HTTPS request
    C->>D: Proxy (security headers)
    D->>M1: Internal HTTP (api:8000)

    Note over M1: Gán X-Request-ID
Bind vào structlog

    M1->>M2: request + request_id

    alt BACKEND_API_KEY set
        Note over M2: Check X-API-Key header
hmac.compare_digest()
        alt Key hợp lệ
            M2->>M3: ✅ Pass
        else Key sai hoặc thiếu
            M2-->>B: ❌ 401/403
        end
    else BACKEND_API_KEY not set
        Note over M2: ⚠️ Dev mode
Warning log, pass through
        M2->>M3: Pass (no gate)
    end

    M3->>R: route request

    alt JWT Protected Route (/api/v1/me, /payment...)
        R->>R: verify_supabase_jwt()
        R->>DB: SELECT staff WHERE auth_user_id = $sub
        R->>R: require_role() check
    end

    R->>S: call service function
    S->>DB: asyncpg query
    DB-->>S: result

    alt Idempotency-Key header present
        Note over S: Check idempotency_key table
→ return cached if exists
    end

    S-->>R: response DTO
    R-->>M3: JSON response

    alt DB connection error
        M3-->>B: 503 + Retry-After: 5
    else Normal
        M3-->>M1: response
        M1-->>D: response + X-Request-ID
        D-->>C: response
        C-->>B: HTTPS response
    end

Notification System — Outbox Pattern

Event-driven notification: business logic ghi event vào event_log (outbox) → worker relay poll → render template → gửi Telegram/Zalo. Không cần RabbitMQ.

sequenceDiagram
    autonumber
    participant S as ⚙️ Service Layer
    participant DB as 🗄️ event_log table
    participant W as ⚡ Worker (--relay)
    participant T as 📝 Templates
    participant TG as ✈️ Telegram Bot
    participant ZL as 💬 Zalo OA

    Note over S,DB: 1️⃣ Business logic tạo event (transactional)
    S->>DB: INSERT INTO event_log
(event_type, payload, event_published=FALSE)

    Note over W,DB: 2️⃣ Worker poll mỗi 30 giây
    loop Every 30s
        W->>DB: SELECT * FROM event_log
WHERE event_published = FALSE
ORDER BY created_at LIMIT 50
        DB-->>W: unpublished events (batch)

        alt Có events
            W->>T: render(event_type, payload)
            T-->>W: notification text

            alt Template exists
                loop Retry up to 3 times
                    W->>TG: send_telegram(message)
                    TG-->>W: ok / error
                end

                alt Success
                    W->>DB: UPDATE event_log
SET event_published = TRUE
                else All retries failed
                    W->>DB: UPDATE event_log
SET event_published = TRUE
