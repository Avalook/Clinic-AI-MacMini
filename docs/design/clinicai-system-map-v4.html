Một engine ở giữa — mọi tính năng là module cắm vào

Đây là tấm bản đồ cấp dự án anh hỏi: không phải luồng bệnh nhân (đó là việc của v3), mà là toàn bộ hệ thống chia thành module thế nào để backend dễ code, và để "thêm tính năng = thêm module" là sự thật kỹ thuật chứ không phải khẩu hiệu. Sáu mockup của sếp đều map thẳng vào bản đồ này — bảng đối chiếu ở mục 05.

Nguyên tắc 1
Engine không biết nghiệp vụ. Nó chỉ biết hàng đợi, trạng thái, cạnh hợp lệ, SLA, validator. Siêu âm hay X-quang với engine là như nhau.
Nguyên tắc 2
Module không GHI chéo. Ghi = qua engine command hoặc event; đọc đồng bộ = chỉ qua interface đã khai (provides/consumes). Cắt một module ra, phần còn lại vẫn chạy.
Nguyên tắc 3
Bề mặt là hàng generic. 4 UI đọc engine — thêm module mới, Điều phối/TV/Workspace tự nhận, không sửa dòng UI nào.
Nguyên tắc 4
Modular monolith. Module = thư mục trong một FastAPI, một Postgres — đúng spec §6, không microservice. Ranh giới để trong code, không để trong hạ tầng.

01 — Bản đồ

5 vành: Bề mặt → Engine → Module nghiệp vụ → Sổ cái & nền tảng → Tích hợp ngoài

Nét teal = gọi API engine. Nét xám = module đăng ký (form + validator + routing) vào engine lúc khởi động. Nét vàng đứt = event một chiều qua outbox. Nét đỏ chấm = ra ngoài tổ chức. Di chuột vào hộp để soi quan hệ.

gọi API engine đăng ký vào engine event (outbox) ra ngoài tổ chức
100%
Đọc board này thế nào: hàng BỀ MẶT không chứa nghiệp vụ — chúng render những gì engine trả về. Hàng MODULE chứa toàn bộ nghiệp vụ — mỗi module sở hữu bảng của nó, phát event của nó. SỔ CÁI là dữ liệu dùng chung chỉ-đọc-qua-service (bệnh nhân, nhân sự, danh mục, cơ sở). NỀN TẢNG là những gì đã chạy trong repo hôm nay: auth per-staff (cluster #1a), event_log outbox, idempotency. CSKH là dải cắt ngang — nó nghe event từ mọi nơi và làm việc bằng case.
02 — Hợp đồng module

Một module phải khai đúng 7 thứ — và chỉ 7 thứ

Đây là cơ chế biến "thêm tính năng = thêm module" thành sự thật. Module nào không khai đủ 6 mục thì không được merge; module nào khai quá (gọi thẳng bảng của module khác) thì bị chặn ở review.

#KhaiLà gìVí dụ (module Siêu âm)
1Bảng sở hữuBảng chỉ module này được ghi. Module khác muốn đọc → qua service/API của nó.ultrasound_record
2APIRouter FastAPI của module, prefix riêng./api/v1/ultrasound/*
3Node đăng ký vào engineInstance nào (execution_site, ca), điều kiện vào, completion validator, cạnh routing.DICH_VU@SA-T2, SA-T4 · validator: ảnh≥1 + kết luận + ký
4FormSchema để Workspace render — không viết màn hình riêng. Mọi bản ghi form có trạng thái DRAFT mặc định («Lưu nháp» trong mockup); validator chỉ chạy lúc Complete.sieu_am.schema.json
5Event phát / ngheTên event vào event_log + event nó subscribe. Mọi billable event bắt buộc mang subject_person_id — và module KHÔNG BAO GIỜ phát giá tiền, chỉ phát usage (thungan là nơi DUY NHẤT định giá, đọc bảng giá + gói từ DANH_MUC).phát ultrasound.completed · nghe service_order.signed
6Provides / consumesInterface ĐỌC đồng bộ module này export, và interface của module khác nó gọi — khai tường minh. Luật: GHI chéo cấm tuyệt đối (chỉ qua engine command/event); ĐỌC chéo chỉ qua interface đã khai.provides: get_result(order_id) · consumes: benh_nhan.get_person
7QuyềnVai nào làm gì, theo ma trận 2 miền (lâm sàng/hành chính) + theo trường.ghi: BS/TKYK · ký: BS · xem: hành chính
# manifest của một module — đây là toàn bộ những gì phải viết khi thêm tính năng
module: xquang                      # ví dụ: phòng khám mở dịch vụ X-quang
owns_tables: [xquang_record]
api: /api/v1/xquang
nodes:
  - template: DICH_VU                 # dùng lại template có sẵn của engine
    sites: [{location: KIM_NGUU, floor: 1, room: XQ-01}]
    entry: [service_order.signed, subject_present]
    validator: [image_count >= 1, conclusion != null, signed_by != null]
    routing: {DONE: CHO_KHAM_LAI, DEFERRED: KET_QUA}
form: xquang.schema.json
provides: [get_xquang_result(order_id)]
consumes: [benh_nhan.get_person]
events: {emits: [xquang.completed], listens: [service_order.signed]}
# validator là BIỂU THỨC KHAI BÁO — engine tự chấm trên dữ liệu, không chạy code của module
# → module ketqua có sập thì hàng đợi các module khác vẫn chạy
permissions: {write: [BAC_SI, TKYK], sign: [BAC_SI]}
# KHÔNG sửa engine. KHÔNG sửa Điều phối/TV/Workspace — chúng tự nhận node mới.

04 — Bài kiểm tra mở rộng

"Thêm tính năng = thêm module" — thử bằng 5 kịch bản thật

Một kiến trúc module chỉ đáng tin khi chỉ ra được chính xác cái gì phải viết và cái gì không được đụng. Nếu kịch bản nào buộc sửa engine hay sửa UI generic — kiến trúc sai, quay lại vẽ tiếp.

06 — Cấu trúc backend

Module = thư mục. Ranh giới nằm trong code, không nằm trong hạ tầng.

src/clinicai/
├── engine/                  # KHÔNG chứa nghiệp vụ — trái tim, viết một lần
│   ├── queue.py               # queue_item + 10 command (Enqueue, Call, Complete, Route…)
│   ├── nodes.py               # node_definition · node_instance (bật/tắt theo ca)
│   ├── transitions.py         # node_transition — cạnh hợp lệ, trưởng ca chỉ chọn trong đây
│   ├── ranking.py             # DỜI services/queue_order.py vào đây (đã có, 9 test) — việc còn lại: bỏ copy hiển thị lib/queue.ts
│   ├── validators.py          # chạy completion validator do module đăng ký
│   └── registry.py            # đăng ký TĨNH: dict Python + import-linter — KHÔNG phải plugin framework runtime
├── modules/                 # nghiệp vụ — mỗi thư mục một module, KHÔNG import chéo
│   ├── dathen/   checkin/   sinhhieu/   kham/
│   ├── dichvu/                # template DICH_VU + các instance: SA · lấy mẫu · thủ thuật · POCT
│   ├── ketqua/                # nhập KQ ngoài + gate duyệt (ghi lab_result — cột gate ĐÃ CÓ)
│   ├── thungan/               # scope thuốc|dịch vụ · đối soát KiotViet · payment DEBT/WAIVED
│   └── cskh/                  # case = staff_task · kịch bản = catalog data, không phải code
│       └── (mỗi module: router.py · service.py · models.py · events.py · forms/ · manifest.yaml)
├── platform/                # đã chạy hôm nay — giữ nguyên
│   ├── identity/              # JWT per-staff → role (cluster #1a)
│   ├── eventlog/              # outbox event_log + relay (append-only trigger đã có)
│   ├── notify/                # Telegram đã chạy · Zalo khi có OA
│   └── files/                 # ảnh SA/XN — artifact ảnh 10–30K hồ sơ
└── integrations/            # mỗi đối tác một connector, cấu hình được — không hard-code vendor
    ├── kiotviet.py            # đối soát, không kéo tiền về (cho tới khi PK quyết khác)
    ├── lab_mail.py → lab_api.py   # email parser trước, API sau — cùng interface
    └── zalo_oa.py
Luật giữ ranh giới (3 dòng, đưa vào CI): (1) modules/* không import modules/* khác — chỉ import engine, platform, sổ cái. (2) Mỗi bảng có đúng một module được ghi — checker đọc owns_tables trong manifest. (3) UI không gọi Supabase trực tiếp trừ auth + realtime (đã là luật của CLAUDE.md).
